# Portside

Local dev-server manager: Go daemon + CLI (`cmd/portside`) with an embedded React dashboard (`web/`). macOS first, Linux supported; Unix-only (process groups, PTYs).

## Commands

- `make build`: dashboard (`pnpm --dir web build` into `web/dist`) and `bin/portside`.
- `make check` runs the checks: `go vet ./...`, `go test ./...` and `pnpm --dir web build`; CI adds `-race`. Tests cover config edits and stable automatic ports, discovery deduplication and Python proposals, directory warnings and terminal launch arguments, Compose menu suppression, process-group termination, server handoff and adoption across an upgrade, log buffering and restoration, live readiness (including IPv6 and health failures), restart cancellation, rename continuity, stale launch settings, crash and config recovery, temporary worktree servers (naming, port choice, subdirectory mapping, persistence and removal; skipped without git), log replies, container attachment, failure and issue rules, persisted stop intent, event reconnect backoff, compose arguments and log WebSocket status/tail, and sharing between devices (pairing codes and keys, request signatures and server proofs, the peer guard, port mirrors giving way to local listeners, chosen local ports, resuming a connection, forwarded ports in the supervisor, Tailscale status and Serve parsing); they need no Docker, Tailscale, external network or real config; readiness checks use isolated loopback listeners. `pnpm --dir web check:contrast` verifies WCAG AA for every theme.
- `make dev-daemon` (isolated daemon on :7980, config and state in `.dev/`; `PORTSIDE_DEV_ORIGIN=5173` lets the dashboard host at that port write), `make dev-open` (sign the browser in; prints the Vite address), `make dev-ui` (Vite on port 5173 proxying `/api` and `/auth`; open it at `http://<dashboard host>:5173`, where the session cookie applies). Clients sign every request with the token in `<state>/auth-token` (never sent); `curl -H "Authorization: Bearer $(cat <state>/auth-token)"` works for manual calls. Browsers get a session cookie through `portside open`, valid only on the dashboard host in `<state>/dashboard-host`.
- Try changes against an isolated instance: `PORTSIDE_CONFIG=/tmp/x/portside.toml PORTSIDE_STATE_DIR=/tmp/x/state` with `port = <free port>` in that config. The user's real daemon runs on :7878; do not stop it or its servers.

## Layout

- `internal/app`: product name, ID, service label (the macOS app's bundle ID is `<label>.app`, read from here by `scripts/build-macos-app.sh`), default port, env prefix. The only place the product name is defined. The version comes from `-X main.version`; the release workflow takes the repository and tap owner from GitHub.
- `internal/config`: TOML loading and validation (`config.go`), comment-preserving field edits of `[servers.<name>]` tables (`edit.go`, `edit_values.go`), automatic port persistence on daemon load, last-good startup fallback (`recovery.go`), starter file, devctl importer.
- `internal/supervisor`: process lifecycle in PTYs (`supervisor.go`), continuous readiness and loopback selection (`readiness.go`), scrollback and log files (`logbuf.go`), environment from the account's login shell (`shellenv.go`; see README "Configuration" for how it is read and refreshed), CPU/memory sampling, persisted state and orphan recovery (`state.go`), handing live servers to a re-executed daemon and adopting them (`handoff.go`), temporary copies of a server for other git worktrees (`worktree.go`; kept in state, never in the config), JSON `View`.
- `internal/docker`: Docker Engine API client over the active context's socket (`endpoint.go`, `client.go`), the live container monitor with events and stats (`monitor.go`), engine start detection (`engine.go`) compose service and project jobs (`job.go`), and deliberate stop persistence (`stopstate.go`). Compose jobs shell out to the docker CLI; lifecycle and logs use the Engine API.
- `internal/server`: HTTP API, WebSockets (`/api/events`, `/api/servers/{name}/terminal`), host/origin guard and `*.localhost` proxy (`server.go`), routes (`routes.go`), plain-text log replies with search and size limits (`loglines.go`). Authentication (`auth.go`): requests signed with the token, a bearer token for manual use, and the dashboard session: the dashboard is served only at `http://d-<24 hex>.localhost:<port>` (random per state directory, reserved by `config.IsDashboardLabel`), the cookie (an HMAC of the token, not the token) is accepted only there, and `127.0.0.1`/`localhost` serve the API plus a sign-in hint without revealing that host. `internal/signing`: the one request-signing scheme (HMAC over method, request URI, time, nonce, body hash and epoch; time window and nonce cache), used by local clients with the token and by paired devices with their key. The JSON shapes here are the dashboard's contract.
- `internal/daemon`: daemon process (lock, listeners, signals; writes `<state>/daemon.port` so clients find a daemon whose config moved to another port). In-place upgrades (`upgrade.go`): `POST /api/upgrade` (denied to peers) checks the given binary, then the main loop writes `<state>/handoff.json`, keeps the lock, listening sockets and server terminals open across `syscall.Exec` and re-executes in the same pid; the new daemon finds the file through a nonce in the environment, adopts the servers before `Recover` and serves on the inherited sockets. On success the request gets no reply; `daemon restart` then waits for the new `startedAt` and version, and falls back to stop and start for a daemon without the route. The stop marker `<state>/stopped` is written by a deliberate stop (`/api/shutdown` without `restart`, `daemon stop`, `service uninstall`) and removed by every daemon start except one taking over from an upgrade, which then stops instead (a stop wins over a pending upgrade); while it exists the macOS app polls `daemon info --no-start` instead of starting a daemon. `daemon info` is the app's contract: JSON on stdout, exit 3 when no daemon runs (`--no-start`), 4 with `configError` when the config does not load. A daemon that loses the lock exits 0, and so does a shutdown, so launchd and systemd only restart crashes. `internal/client`: CLI-to-daemon HTTP client with auto-spawn (through the login service when it runs this daemon); it signs every request and WebSocket dial (`DialWebSocket`) and never sends the token. A daemon from before signed requests answers 401, so `daemon restart` and `stop` send it SIGTERM after checking it is this user's listener on the port (`shutdown` in `internal/cli/daemoncmds.go`).
- `internal/cli`: commands. `internal/mcpserver`: MCP tools over stdio (servers, containers, logs with `match`). `internal/agentskill`: the agent skill (`skill.md`, a template filled from `internal/app`), installed by `portside skill install` and refreshed by the main daemon on start; keep it in line with the CLI and MCP tools. `internal/service`: launchd/systemd (install, start and restart through the service, systemd linger check). `internal/discover`: project detection, configured-command filtering and shared port suggestions for the API and CLI. `internal/ports`: listener lookup via `lsof`/`ss`.
- `internal/tailnet`: Tailscale status and Serve entries through the tailscale CLI. `internal/share`: lets the owner's paired devices in (Serve entry, listener and request checks in `share.go`, pairing codes and device tokens in `devices.go`). `internal/remote`: connects to another device's daemon (discovery, pairing, connecting and resuming in `peers.go`; `/api/peer` relay, `/api/tunnel` port tunnels and forwarded ports in `remote.go`; the macOS check for a local listener next to a forwarded port in `probe.go`; the saved connection and chosen local ports in `store.go`). The CLI reaches the connected computer through `client.On` (`--on`, `internal/cli/computers.go`), MCP tools through their `computer` argument. `internal/server/remote.go` holds their routes, the peer handler and `<name>.<computer>.localhost`; `web/src/features/remote` and the `/api` base switch in `web/src/api/client.ts` are the dashboard side.
- `internal/server/containers.go`: container routes; logs, shell and job output stream over the same terminal WebSocket protocol as servers. Container ownership is in `containerowners.go`: explicit project names (servers sharing one ordered by the closest directory), closest Compose working directory, or a local CLI project ID from repository-bounded config lookup, over configured and temporary servers. It also watches container issues and uses the supervisor notifier guard.
- `web/`: dashboard (Vite, React, xterm.js); `web/embed.go` embeds `web/dist`. Themes: `web/src/styles/themes/*.css` are copied unchanged from the shared ui-theme catalog; Portside's own per-theme tokens live in `web/src/styles/semantic.css` and terminal palettes in `web/src/theme/terminal.ts`.
- `macos/`: Swift menu bar app (AppKit status item + SwiftUI panel, WebKit dashboard window); `scripts/build-macos-app.sh` assembles `dist/macos/Portside.app` with the Go binary in `Contents/Helpers/portside`. `make app-install` installs it (update steps in README "Install").
- `packaging/homebrew/portside.rb.tmpl`: cask rendered by the release workflow.
- `design/`: app icons (`design/brand`: tug light/dark), compressed concept and icon explorations (`design/explorations`; full-size originals live untracked in `design/originals`), screenshots used by the README (`scripts/screenshots.sh`; `--portfolio DIR` writes light/dark pairs and renders the menu bar panel offscreen with the app's `--render-panel=PATH` flag). The menu bar glyph is drawn in code (`macos/Sources/Portside/StatusIcon.swift`).

## Constraints

- Never use the em dash character in code, comments, UI copy (English or Polish) or docs.
- Keep the product name out of identifiers; derive user-visible names and env vars from `internal/app`.
- macOS builds target Apple Silicon only (arm64); keep `scripts/build-macos-app.sh` and `.goreleaser.yaml` in line with the README requirements.
- Config edits must go through `internal/config` so comments survive and invalid text never reaches disk.
- Process termination always targets the process group (`-pgid`): SIGINT, then SIGTERM, then SIGKILL.
- pnpm is pinned to 12.6.0 with `minimumReleaseAge: 1440`; ask before adding `trustPolicy` exceptions.
